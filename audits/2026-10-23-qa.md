## Blocker

### QA-001: The merchant demo login is rejected, so the whole dashboard is unreachable
- **Area:** Dashboard / auth
- **URL:** https://housekind.openship.org/dashboard/signin
- **Steps:** Sign in with the `rental` credentials from `~/Code/Euler/state/launch-four-demo-logins.json` (`housekind@openship.org`). Also tried directly with the `authenticateUserWithPassword` GraphQL mutation.
- **Expected:** The host lands on the dashboard.
- **Actual:** "Unable to sign in. Check your email and password and try again." The API returns `UserAuthenticationWithPasswordFailure: Authentication failed.` The host can't recover access either: dashboard password reset can't send email (QA-004), and `/dashboard/signup` redirects back to sign-in.
- **Impact:** No dashboard section (Today, Calendar, Reservations, Listings, Properties, Pricing, Guests, Inbox, Payments, Payouts, Reports, Tasks, Reviews, Channels, Agreements) could be QA'd. The leftover "QA Codex R2" listing (QA-003) shows an earlier round did sign in, so the password or user has changed since then.
- **Likely fix:** Operational. Reset the `housekind@openship.org` password (or re-seed that user with a role where `canAccessDashboard` is true), update the logins file, then rerun the dashboard half of this QA. If the reset should already have worked, check the seed or onboarding script that creates the demo user (`features/keystone/onboarding`, `scripts/`).

## Major

### QA-002: Guests can't pay online; instant-book homes create unpaid reservations
- **Area:** Storefront / checkout / payments
- **URL:** https://housekind.openship.org/checkout/<quoteToken> (reached from `/stays/pineglass-cabin?checkIn=2026-11-16&checkOut=2026-11-19&adults=2`)
- **Steps:** Pick dates on any home, then click Reserve or Request to book.
- **Expected:** A vacation-rental direct-booking site takes a deposit or full payment at booking (Stripe), or at least offers the test-booking card checkout the code supports.
- **Actual:** "Payment arranged with the host. Your reservation starts unpaid. Agree the payment method and timing with your host after confirmation." No Stripe step and no "test booking" option (`testBookingsAvailable` is false). `/policies` says "this website doesn't take card payments". For instant-book homes (Juniper, Foundry, Pineglass), anyone can block real dates with no payment or commitment. The $500–$1,250 security deposits are also collected entirely off-platform.
- **Likely file:** Configuration rather than code: the Stripe payment provider and marketplace settings (`features/keystone/models/PaymentProvider.ts`, `MarketplaceSettings.ts`, `features/platform/store-settings`). Gating is in `features/storefront/screens/checkout/StayCheckoutPage.tsx` (`testBookings`, `paymentBody`). The fixer must not change Store Settings on the live store without the owner; raise it with them. Code-side, consider refusing instant book when no payment provider is active, or auto-expiring unpaid instant reservations.

### QA-004: No transactional email: guest password reset is disabled, and dashboard reset falsely says "sent"
- **Area:** Auth / email
- **URLs:** https://housekind.openship.org/account/reset, https://housekind.openship.org/dashboard/reset
- **Steps:**
  1. Open `/account/reset`.
  2. Open `/dashboard/reset`, enter an email, and submit.
- **Expected:** Reset emails are delivered. If email isn't configured, both flows say so honestly.
- **Actual:**
  1. The guest page shows "Password reset by email isn't available for this store yet", yet the sign-in page still advertises "Forgot your password? Reset it" and leads to this dead end.
  2. The dashboard page shows "SUCCESS: Password reset link has been sent to your email." In `features/keystone/index.ts` `passwordResetLink.sendToken`, the send failure is swallowed, and the dashboard action never checks `passwordResetEmailConfigured()`, so host staff are told an email is coming that never arrives. With no SMTP, guests also get no booking confirmation or host-reply notifications by email; they must keep the private link.
- **Likely file:** `features/dashboard/actions/auth.ts` (~line 124: reset branch, should check mail availability like the guest flow), `features/keystone/lib/mailAvailability.ts`, `features/keystone/index.ts:77`, `features/storefront/screens/account/AccountAuthPages.tsx` (hide the "Reset it" link when unavailable). SMTP env setup is ops work (`SMTP_HOST`, `SMTP_FROM`, `SMTP_STORE_LINK`).
